# Spacefast for WordPress

One WordPress plugin, two ways to publish a static site to Spacefast:

- **Static WordPress** uses the free [Simply Static](https://wordpress.org/plugins/simply-static/)
  plugin to generate HTML, CSS, JavaScript, and assets. Spacefast publishes the
  generated directory as an exact snapshot.
- **Headless CMS** treats WordPress as a public content source. Content changes
  rebuild the connected Astro or other repository project on Spacefast.

## Install

1. In Spacefast, open the Space's WordPress data-source setup and choose
   **Connect WordPress**.
2. Download [`spacefast-wordpress.zip`](https://github.com/spacefast/wordpress/releases/latest/download/spacefast-wordpress.zip)
   and create the one-time connection.
3. In WordPress, upload and activate the ZIP, then open **Settings → Spacefast**.
4. Paste the complete connection, choose a publishing mode, and test it.

The generated credential is scoped to one Space. It can trigger that Space's
production repository, publish static files to it, and read its version status.
It cannot edit WordPress, change Space settings, manage domains, or access
another Space. The secret is stored in a non-autoloaded WordPress option and is
never displayed after save. A managed host can instead define
`SPACEFAST_WORDPRESS_API_URL`, `SPACEFAST_WORDPRESS_SPACE_ID`, and
`SPACEFAST_WORDPRESS_TOKEN` in `wp-config.php`.

## Static WordPress

Install and activate Simply Static, then select **Static WordPress** in
**Settings → Spacefast**. **Export and publish** starts a full Simply Static
export. Starting an export from Simply Static's own screen works too.

Spacefast adds a delivery step after Simply Static has generated and delivered
its files but before cleanup. The step hashes the generated bytes, declares a
full export as an exact snapshot through Spacefast's normal version API,
uploads only the files Spacefast requests, waits for activation, and records
whether that version became live. Partial, update, build, and 404-only exports
are additive so they cannot accidentally delete omitted site files; run a full
export after deleting content. Upload transfer is paged and processed one file
per Simply Static background step so a large upload does not become one
unbounded WordPress request.

Simply Static remains responsible for crawling WordPress and rewriting URLs.
Spacefast never reads drafts, WordPress credentials, or the database. Dynamic
WordPress features still need a static-compatible replacement.

## Headless CMS

Select **Headless CMS** when an Astro or other repository project reads the
WordPress REST API during its build. Publishing, updating, unpublishing, or
deleting public REST-visible post types, taxonomy changes, navigation changes,
media changes, and public user changes schedule a production build. Autosaves,
revisions, and draft-only transitions are ignored. Multiple hooks in one
request collapse into one generation.

Delivery uses WP-Cron with a stable idempotency key. Network failures, timeouts,
rate limits, and server errors retry with bounded exponential backoff. A change
arriving while a delivery runs remains pending and schedules one successor.
**Build now** uses the same path immediately. The generic **Build now** action
in the Spacefast dashboard triggers the same connected production repository.

The plugin sends no post content, title, author, or other WordPress data to
Spacefast. It sends only the configured public WordPress origin and a request
to run the server-owned repository settings.

## Operate and remove

The settings page shows the active mode, pending work, delivery status, and the
last build or version ID. It also provides a connection test and appears in
Site Health.

**Disconnect** removes the local secret and pending work. Revoke the matching
WordPress key in Spacefast Developer settings. Uninstall removes all plugin
options, cron events, locks, notices, and interrupted static-publish state; it
never deletes WordPress content or Simply Static exports.

## Development

From this directory:

```bash
./bin/test.sh
```

This lints every runtime PHP file, runs dependency-free behavioral tests, builds
the deterministic installable ZIP in `dist/`, checks the archive, and proves a
second build produces identical bytes.

Private beta supports WordPress 6.5+, PHP 8.1+, and Simply Static 3.8+ for direct
static publishing. Activate it per site; network activation is intentionally
rejected so a credential can never be silently shared across a multisite
network.
